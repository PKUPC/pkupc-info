# 项目适配与离线来源说明

本文件是执行备注，不是 SOP 原文。全文来源见 [lark-sop.md](lark-sop.md)，修订版本 1095。开始执行时重新检查当前代码、模板和来源文件。

## SOP 与当前项目的差异

- SOP 的“对应谜色的序号标签”是历史文字；此 Skill 处理执笔编号，需建立清单到 `zhibi-NNN` 的明确映射。
- 当前目标目录是 `content/wechat-official-account/zhibi/`，模板为 `scripts/templates/zhibi-000.mdx`；`pnpm gen-template zhibi N` 会覆盖文章，必须先确认不存在。
- 当前注册的是 `Solution`，不是 SOP 一处写的 `Solutions`。组件从 `src/theme/MDXComponents.js` 注册，无需在文章重复导入。
- SOP 多解示例遗漏了 `mitiType="zhibi"`，实际迁移时所有纸笔验证器均需补上。
- SOP 代码导出可能含 `\'` 等转义，不能把导出文本原样当可编译 JSX。参考当前模板和已迁移文章写代码，不改写 SOP 来掩盖差异。
- `authors.yml` 存作者 ID，`tags.yml` 为同 ID 设置作者名字标签。按 CONTRIBUTING 每篇 `tags` 包含全部出题作者和 `zhibi`；作者 `url` 指向对应标签页。新增作者资料仅用原文或用户确认值，不猜头衔、QQ、头像。
- 作者已存在于 `authors.yml` 不代表其标签已定义。核查 `tags.yml` 的实际同名键；构建成功仍可能输出未定义标签的警告，须查看日志并在页面末尾确认中文标签名称和跳转。033/034 首次验证曾漏补 `soliloquies` 标签，已补齐“怎苏昂”名称及标签路径。
- `<AnswerCheck>` 的真实接口见 `src/components/AnswerCheck.tsx`，归一化见 `src/utils/formatString.ts`：只保留中文、数字和英文字母，字母转大写。答案键归一化后若冲突，需先判断是否本就同一提交结果，不写会被覆盖的不同反馈。
- `Solution` 和原生 `<details>` 用于遮挡解答；`CarouselInner` 是轮播步骤容器。最终解可用 Markdown 图片，步骤容器内图片使用 `<img src={require('./zhibi-NNN.assets/zhibi-NNN-sol-1.webp').default} />`。不要使用动态资源路径。
- 当前公众号 Markdown 图片未自动套用 `CustomImage`，轮播原生 `<img>` 也不自动支持放大；图片预览验证应记录真实行为。模板与既有文章中的占位文案不代表新文章的主题简介。

- 规则/提交格式的小型示例图使用静态 `require(...).default` 的 `<img>`，设置 `width: '100%'`、`maxWidth: 320`、`height: 'auto'` 与居中；避免按约 600px 的原图尺寸铺开。题图、最终解和步骤图不套用这个小图宽度限制。

## 按题型选择已有例子

- 普通单解及步骤：`content/wechat-official-account/zhibi/zhibi-022.mdx`、`zhibi-024.mdx`。
- 隐藏规则、双解与后记：`content/wechat-official-account/zhibi/zhibi-009.mdx`。保留原规则、隐藏规则和对应解的独立结构，不默认所有双解都来自隐藏规则。
- Double Clue、Two Pieces 等题按原文的机制编排，不能直接套彼岸双生的“隐藏规则”文案。
- Double Clue 的两套规则共同约束一个唯一解，不代表有两个可分别提交的答案。首批 025/026 的正确值需从后续推文的正式解图按原题提交规则提取；公众号的 `DC01` / `DC02` 是路由口令，网页只输入提取出的数字串，示例也同步去掉前缀并保留前导零。
- 提取时同时查看题图中的箭头/行列标记和规则文字；不能只读 HTML 正文。“空格数”要按该题定义区分未经过的空格与灰色提示格、粗框无数字格；颜色相似不代表相同类别。识别结果与公众号核验状态分别记录，由用户完成公众号验证。
- 空格计数先从原题建立预置提示格坐标清单，再逐行列出解图中未经过的格子坐标，逐格排除预置提示格并复数一遍。首批 026 曾把 G8 误当提示格漏数；原题 G8 是普通空格，第八行为 A8、E8、G8 共 3 格，修正值已获用户公众号核验。不能只凭缩略图或灰色/黑色填充判断是否是提示格。
- 按每题提交文字确认编码，不能沿用同主题上一题的编码。例如 029 的转弯/直行是 1/0，030 则是 2/1；028 空格用 X，数字 0 仍是数字。逐行黑格数先记录完整计数再取个位，保留 10 格对应的前导 0。
- 解图的灰色可能表示黑格，绿色可能表示留白。可用像素颜色辅助复数，但先目视确认颜色含义，并避开数字、箭头、圆圈和网格；最终用全尺寸解图核对坐标，不能把文字的黑色像素算作黑格。
- 解析署名可能在同一主题中变化，逐篇读取解析段落署名。原文的期次或重复用词疑点记入批次记录，未经用户确认不擅自改正。
- 不言自明系列的规则发现机制、黑方块题名及提示应按原文保持遮挡；不能从正式解析提取规则后提前展示给做题者。
- 原文标有 A/B、多个盘面或多个答案时，以原文确认区别，不能仅凭图片数量判断为几道题。
- 真知之岛每题规则不同，正文可能只给出一条规则，其他规则只出现在题图或规则图里。逐条识别图片中的全部文字和禁止图案，转写为规则正文并保留原规则图；不能将后续题目的条件套用到首题。034 的白区域单线索、黑格连通及禁止全黑 2×2 均来自规则图，033 则仅要求数字表示所在区域的面积。
- 简介与规则图矛盾时保留原文差异，结合正式解图核对，在页面明确注明编排依据，不静默改写。例如 037 简介写“黑格连通”，规则图写“白格连通”，正式解图的黑色区域各为 3 格且互不相连，因此正文按规则图整理并注明差异。
- 插入特别篇后，归档序号与正式编号可能不再一致。本批归档 041 的真知之岛第八题实际标为 #040，使用 `zhibi-040`；其解析在归档 042 中，题图标 #041 的下一个主题不属于本批。归档 041 同时有九月九日特别篇解图，截取第七题解析时须在特别篇标题之前结束，不能并入另题解图。
- 两篇九月九日特别篇（归档 040、067）的题图均标为 #999，分别使用 `zhibi-999-2025` 与 `zhibi-999-2026`。原文明确不设置后台验证，不添加验证器或提交格式。2025 解图在归档 041 的“⑨月⑨日特别篇答案”段，作者怎苏昂；2026 归档没有独立正式解图，按用户本次明确迁移要求保留题目页，在批次记录注明缺解图，不伪造解析。
